# Power BI Desktop Integration & Dashboard Setup Guide

## 1. Overview
This guide provides complete instructions for connecting **Microsoft Power BI Desktop** to the verified data exports generated by the FraudGuard PySpark pipeline.

All data sources referenced here are direct, genuine CSV exports from `powerbi/data/`.

## 4. Key DAX Measures

Create a new table or measure group called `_FraudGuard_Measures`:

```dax
// 1. Fraud Rate Percentage
Fraud Rate % = 
DIVIDE(
    SELECTEDVALUE(dataset_summary[fraud_records], 0),
    SELECTEDVALUE(dataset_summary[total_records], 1)
) * 100

// 2. Average Precision
Model Precision = AVERAGE(model_comparison[precision])

// 3. Average Recall
Model Recall = AVERAGE(model_comparison[recall])

// 4. Model F1-Score
Model F1 = AVERAGE(model_comparison[f1_score])

// 5. Total False Positives
Total False Positives = SUM(model_comparison[false_positives])

// 6. Total False Negatives
Total False Negatives = SUM(model_comparison[false_negatives])

// 7. Optimal Threshold Cost ($)
Minimum Operational Cost = MIN(threshold_analysis[total_operational_cost])
```

## 5. Dashboard Page Design Specifications

### Page 1: Fraud Overview
- **Visual 1 (Card Visuals)**:
  - Total Transactions: `SUM(dataset_summary[total_records])`
  - Genuine Transactions: `SUM(dataset_summary[legitimate_records])`
  - Fraud Transactions: `SUM(dataset_summary[fraud_records])`
  - Fraud Rate: `[Fraud Rate %]` (e.g., 3.5% or 0.17%)
- **Visual 2 (Donut Chart)**:
  - Legend: Transaction Class (Legitimate vs. Fraudulent)
  - Values: Count of records
- **Visual 3 (Table / Matrix)**:
  - Partition Breakdown: Train Records (70%), Validation Records (15%), Test Records (15%).
  - Feature Dimensions: Numerical Features count vs. Categorical Features count.

### Page 2: Fraud Pattern Analysis
- **Visual 1 (Clustered Column Chart)**:
  - Transaction volume and fraud prevalence grouped by categorical features (e.g., `ProductCD`, `card4` network, or device types).
- **Visual 2 (Line Chart)**:
  - Transaction velocity over time (`TransactionDT` chronological progression).
- **Visual 3 (Slicer)**:
  - Slicer for filtering by specific product types or card brands.

### Page 3: Model Performance Comparison
- **Visual 1 (Clustered Column Bar Chart)**:
  - X-Axis: `model_name` (Logistic Regression, Decision Tree, Random Forest, GBT, LinearSVC)
  - Y-Axis Values: `precision`, `recall`, `f1_score`, `roc_auc`
  - Title: *"Held-Out Classifier Comparison"*
- **Visual 2 (Comparison Table / Matrix)**:
  - Columns: Model Name, Precision, Recall, F1-Score, ROC-AUC, PR-AUC, Training Time (sec).
  - Conditional Formatting: Data bars on F1-Score and ROC-AUC.
- **Visual 3 (Confusion Matrix Heatmap)**:
  - Slicer: `model_name`
  - Visual: 2x2 Matrix showing True Negatives, False Positives, False Negatives, and True Positives.

### Page 4: Risk & Decision Threshold Analysis
- **Visual 1 (Dual-Line Chart — Trade-off Curve)**:
  - X-Axis: `threshold` (0.05 to 0.95)
  - Lines: `precision` (Blue), `recall` (Red), `f1_score` (Green)
  - Title: *"Precision vs. Recall Operational Frontier"*
- **Visual 2 (Cost Minimization Area Chart)**:
  - X-Axis: `threshold`
  - Y-Axis: `total_operational_cost`
  - Title: *"Total Operational Financial Loss by Classification Threshold"*
- **Visual 3 (Stacked Bar Chart)**:
  - X-Axis: `threshold`
  - Values: `false_positives` (Customer Friction) and `false_negatives` (Undetected Fraud)
